# Claim registry — TRIGGER (the runtime that evaluates a map's authored mission script)

Level 2 ledger. Index: [registry.md](registry.md) · spec: [`formats/trigger/format.md`](../formats/trigger/format.md). Legend: `✔ promoted` (also in the spec) · `● active` · `✖ retracted`. IDs are permanent.

This ledger is the **other half** of `claims/alm.md`'s type-7 rows. Those describe what a
map *stores*; these describe what `rom.exe` *does with it* — who evaluates the conditions,
on which clock, what can be tested, what a fired trigger can do, whether it fires again,
what survives a save, and what decides the mission is over. The map's bytes stay in
`claims/alm.md`; the clock and the session object are `claims/session.md`; the save
container is `claims/sav.md`.

Vocabulary note, because the engine's own words differ from the editor's: a condition is an
**instant**'s counterpart called a *check*, an action is an *instant*, and a trigger is a
*pattern* (`"Failed to create check %d %s"`, `"Failed to create instant %d %s"`,
`"Reference to suspicsious instant (%d) from pattern %d."`).
